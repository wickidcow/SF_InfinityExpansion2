# InfinityExpansion2 2.0.16 — Mob Data Card Refresh and Compatibility

InfinityExpansion2 2.0.16 promotes the tested Mob Data Card refresh changes that were developed after 2.0.15. The standalone addon uses the canonical `SF_InfinityExpansion2.0.16.jar` name, targets Java 21 bytecode on Minecraft 1.21.11+, and is checked against Paper 26.2 and 26.3 with Java 25 API compile jobs.

## Changes

- Restore and modernize **Mob Data Card appearance** so cards display their intended category material, names, lore and model metadata without discarding typed persistent data.
- Refresh old inventory-held cards safely when a player interaction makes them accessible. Defer inventory mutation to the owning entity scheduler, coalesce redundant refreshes, and avoid silently rewriting unrelated or virtual inventories.
- Preserve generic and per-mob card identities, existing quantities (including 64-item legacy stacks), player names, item models, extra lore, custom metadata and associated Mob Simulation machines.
- Add configuration-driven refresh controls and an explicit migration/identity boundary. This **does not rewrite offline players, unloaded chunks or every closed container**.

## Evidence and limitations

The [Mob Data Card validation report](../MOB_CARD_REFRESH_VALIDATION.md) records **183 unit tests** and a native Paper 1.21.11 isolated probe with **535 assertions across 22 scenario groups**. Paper 26.2 and 26.3 source/API compilation also passed. The release-candidate workflow now checks current Slimefun Legacy and Networks source contracts as well as the old 1.21.11 bytecode floor; all its required jobs must pass before release.

InfinityExpansion2 already retains the conservation/recovery fixes from 2.0.15, including correct partial debit, storage identity, rollback and clean restart behavior. No unrelated recipes, IDs or storage schemas were changed in this promotion.

**Folia cross-region runtime behavior is not declared or certified by this addon.** The tests do not substitute for your actual server's loaded-chunk/long-term storage checks. Back up the world and plugin storage before upgrading.

## Installation

Stop your server, back up worlds and InfinityExpansion2 storage and configuration, replace the previous addon JAR with `SF_InfinityExpansion2.0.16.jar`, and restart normally (not `/reload`). Keep the published 2.0.15 JAR and matching backup for an intentional rollback. Do not run both versions simultaneously.

No Geyser/Bedrock integration is added, and existing optional resource-pack files are unchanged.
