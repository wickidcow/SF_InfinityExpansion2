# InfinityExpansion2 2.0.19 — Cargo ItemStackWrapper compatibility candidate

**Release status: DRAFT — NOT PUBLISHED.** This is a proposed distinct successor to the immutable [v2.0.18](https://github.com/wickidcow/SF_InfinityExpansion2/releases/tag/v2.0.18).

## Scope
- Includes reviewed [PR #76](https://github.com/wickidcow/SF_InfinityExpansion2/pull/76): a Cargo source can pass Slimefun's immutable `ItemStackWrapper` into IE2's registered-item presentation check. The previous implementation called `clone()` on the wrapper and threw `UnsupportedOperationException`, blocking Storage Unit insertion. The corrected comparison uses fresh ordinary stacks and independent cloned ItemMeta without altering the original wrapper.
- Identity and safety remain strict: same registered Slimefun ID, material, name and all lore text/formatting, model and owner PDC, and every non-presentation item component. Foreign, mismatched, unidentified or unsafe stacks are not merged.
- Includes merged [PR #77](https://github.com/wickidcow/SF_InfinityExpansion2/pull/77): automatic upstream conflict evidence, with no automatic adoption of potentially unsafe upstream changes.
- No migration, machine rate, recipe, stored amount, automatic player inventory repair, item ID, key or persistence format changes.
