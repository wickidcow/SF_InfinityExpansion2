# InfinityExpansion2 2.0.17 — Modern APIs, preserved machines and item data

This patch integrates the tested energy, generator, ticker, storage and presentation modernization work into one versioned addon. The canonical output is `SF_InfinityExpansion2.0.17.jar`, with Java 21 bytecode for Minecraft 1.21.11 and newer supported Paper APIs.

## Changes

- Migrate machine energy access to long-valued APIs without changing configured capacities, costs, production rates, recipes or processing order.
- Use modern generator/ticker callbacks directly while retaining historical public callback signatures for compiled-addon compatibility.
- Replace direct legacy storage lookups with controller-backed reads that preserve conditional loading, stored identity and error behavior. Failed reads are not interpreted as empty storage.
- Use Adventure for action bars and item lore; retain existing rich components, RGB colors, hover/insertion metadata and typed persistent identities.
- Check metadata transfer during material conversion, preserving old card stacks and custom artwork. Modernize enchantment/instrument lookups and event construction without changing the existing cancellation sequence.
- Remove blanket production deprecation suppressions. CI checks the full own-source warning set and rejects new actionable usage. Seven historical Config signature references and one Paper-required damage-modifier reference remain explicit compatibility boundaries; bundled library internals are not claimed rewritten.

## Validation and limits

Publication is gated on the full regression suite, independent pinned-core API compilation, existing migration/transport safeguards, Java 21 packaging, and disposable native Paper 1.21.11/Java 21 and Paper 26.3/Java 25 runs. The native probes exercise card metadata, registry-backed horn variants, oscillator conversion, cancellable damage notifications, live stored-record identity and a physical menu item across a clean JVM restart.

These checks do not certify every historical world, connected-player/cargo stress, every Purpur/Leaf build, or Folia cross-region behavior. No new Folia capability is declared. Existing IDs, quantities, persistent keys, configuration defaults and recipes remain unchanged. No Geyser/Bedrock integration is added.

## Installation

Stop the server and back up worlds, Slimefun storage, and InfinityExpansion2 configuration/data. Replace only the old addon JAR with `SF_InfinityExpansion2.0.17.jar`; do not keep both versions installed. Start normally, not with `/reload`. Keep all existing data and configuration; no reset is required. For rollback, use the matching backup and previous addon version together. This release does not deploy itself to a live server.
