# InfinityExpansion2 v2.0.22 — historical item typed-PDC diagnosis (read-only)

Distinct successor to the unchanged official [v2.0.21](https://github.com/wickidcow/SF_InfinityExpansion2/releases/tag/v2.0.21). Original InfinityExpansion2 and Slimefun authors remain credited.

## What changed

- `/ie2 doctor compare` continues to read the two **actual player-held** items and independently compare registered Slimefun and GEO resource templates, including Adventure name/lore trees, source-specific serialized field names, Bukkit isSimilar and PDC identity. It **never updates a held item**.
- For a PDC key present in both items, the diagnostic now reports **different primitive storage types** without revealing the stored values. For example, a saved `owner` key stored as `STRING` versus `LONG` is explicitly shown as `owner (STRING/LONG)`. BYTE/SHORT/INTEGER/LONG/FLOAT/DOUBLE/STRING and the three primitive array types are supported. Unknown/adapted types are shown only as `OTHER`, not guessed.
- Missing PDC keys remain separately classified from same-key/different-type keys; different private values stored using the *same type* still produce `PDC=DIFFERENT` but do **not** falsely claim a type migration.
- Existing source-evidence receipts remain text-redacted and bounded; they print key names and type labels, never PDC contents, owner IDs, item text, skull textures or secret payloads.

## Regression and release requirements

- Four focused MockBukkit tests cover synthetic historic-versus-fresh `SMALL_URANIUM` with same Slimefun ID but differing typed owner/ledger PDC, missing keys, same-type unequal values, redaction, and **byte-exact source stack immutability**.
- Existing actual Paper GEO source tests cover the **current registered source** `SMALL_URANIUM`, `/sf cheat` template, guide, actual `GeoQuarry.process -> BlockMenu.pushItem` output, item entity, Bukkit inventory stacking and two-boot persisted identities.
- Release only after source-pinned Gradle full build, all migration/Doctor/transport checks, native Paper 1.21.11, 26.2 and 26.3 regression/restart gates, exact merged-master CI, raw Java 21 `SF_InfinityExpansion2.0.22.jar` checksum and immutable new `v2.0.22` tag validation.

## Compatibility limits

**This is a diagnostic improvement, NOT a historical stacking repair.** A matching Slimefun ID does not make old/new Bukkit `ItemStack` identities equal. Synthetic mismatches do not prove the exact AlbionMC old-item root cause, and current GEO producer parity does not certify historical chests, machines, barrel stock or old QuickShop-Hikari sale templates.

No legacy inventory, storage ledger, quantity, owner PDC, shop record, item construction, migration setting, core source, Unified project or existing release is changed. Historical Chinese IE2 storage/machine acceptance remains separately tracked in [IE2 #73](https://github.com/wickidcow/SF_InfinityExpansion2/issues/73); source-localized GEO evidence in [IE2 #82](https://github.com/wickidcow/SF_InfinityExpansion2/issues/82) and systemic repair in [Slimefun Legacy #615](https://github.com/wickidcow/Slimefun-Legacy/issues/615).

## Deployment

Back up the server, world, player inventory and plugin databases. Install only the distinct, independently verified official `v2.0.22` raw JAR; keep `v2.0.21` for rollback. On a disposable staging copy, compare genuine old `SMALL_URANIUM` (main hand) against newly generated `/sf cheat` or real GEO output (offhand) with `/ie2 doctor compare`. Share only the **redacted** output; do not publish raw item/PDC values. The core project independently controls its future 44-addon ZIP. v4.1.81 ZIP and older addon tags remain immutable.
