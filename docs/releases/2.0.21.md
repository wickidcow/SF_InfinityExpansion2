# InfinityExpansion2 v2.0.21 — GEO producer template-copy isolation

Distinct successor to the unchanged, officially published [v2.0.20](https://github.com/wickidcow/SF_InfinityExpansion2/releases/tag/v2.0.20).

## Source safety

- Ordinary GEO Quarry outputs and guide-display recipes now clone registered GEO resource items **before** setting their respective output amounts. Weighted resource selection, supply rates, crafting, machine speed and quantities are unchanged.
- Preserve exact Adventure name/lore trees, material, Slimefun ID, typed owner and ledger PDC, skull profile and model components; do not create or rewrite historical item bytes. Rare/discovery and DracFun paths already clone templates and remain unchanged.
- This guard reduces risk from future changes in item-editing libraries and from downstream output mutations; it is not proof the previous method caused the AlbionMC historical metadata mismatch.

## Tests and release gates

- MockBukkit PLAYER_HEAD tests cover distinct registered output and guide clones, serializations of source items unchanged, rich historical Adventure formatting preserved, original typed STRING/LONG/BYTE_ARRAY PDC retained, and differing Slimefun IDs and owners never merged by identity.
- Existing native real SMALL_URANIUM tests exercise registered Slimefun and GEO templates, actual GeoQuarry.process -> BlockMenu.pushItem, Paper inventories, dropped entities, and restart preservation. Source templates and production amounts must stay unchanged.
- Require exact-head full Gradle and six source checks, Paper 1.21.11/26.2/26.3 native tests, successful merged-master provenance and raw SF_InfinityExpansion2.0.21.jar with its verified SHA-256. No existing tag or prior asset replacement.

## Important limitation

**Historical item stacking is not fixed.** Old saved SMALL_URANIUM, machines, barrels or QuickShop-Hikari templates can still differ from fresh /sf cheat through nested Adventure component shape. The old physical serialized bytes and responsible historical producer remain unproven. Use existing read-only /ie2 doctor compare before considering a narrowly proven source-specific fix; no automatic migration or ID-only matching is enabled.

## Deployment

Back up world and plugin/inventory data, replace the old IE2 JAR with the official distinct release only after its checksum is confirmed, remove duplicate plugin jars, and check GEO Quarry, inventory/cargo, and clean restart. Retain v2.0.20 as rollback. No configuration change needed.

See [IE2 #82](https://github.com/wickidcow/SF_InfinityExpansion2/issues/82) and [core #615](https://github.com/wickidcow/Slimefun-Legacy/issues/615). The Slimefun Legacy core, 44-addon ZIP and Unified are separate projects and are not modified.
