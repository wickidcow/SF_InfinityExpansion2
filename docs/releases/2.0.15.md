# InfinityExpansion2 2.0.15

This release coordinates storage ownership and recovery with Networks Expansion.

- Storage input, output and player withdrawals retain ownership until the actual slot or inventory change is verified. Partial insertions debit only the accepted quantity; reentrant operations cannot reuse the same stock.
- Breaking a Storage Unit prepares its exact stored identity and contents before mutation. Physical output remains accounted for even when Void Excess is enabled, and foreign item metadata is preserved separately.
- Cancelled item spawns roll back captured drops before source restoration. Unverifiable outcomes remain held for recovery rather than receiving a speculative refund or guessed identity.
- The synchronized Infinity Dust Extractor producer repair from 2.0.14 remains in place. Recipes, IDs, production costs, storage formats and configured rates are retained.
- Existing master fixes for stale Mob Simulation card appearance are preserved by the integration.

The distributable is `SF_InfinityExpansion2.0.15.jar`, built for Java 21 bytecode and the Paper 1.21.11 API floor. CI separately compiles against Paper 26.2 and 26.3 using Java 25. Use the matching Networks Expansion release and the verified GuGu Slimefun Legacy core. Native acceptance evidence is recorded in the companion Networks completion checkpoint and `docs/native-storage-break-receipts.md`.

Folia runtime support is not declared by this addon. Paper/Purpur validation does not establish safe cross-region network transactions. Recovery receipts cover observed synchronous outcomes and clean restart; they do not claim atomic persistence across an arbitrary process crash.
