# InfinityExpansion2 2.0.18 — Identity-safe storage presentation recovery

This follow-up release improves compatibility with historical Slimefun items whose Adventure display name or lore was serialized with an extra **empty, unstyled** wrapper. The canonical distributable is `SF_InfinityExpansion2.0.18.jar` with Java 21 bytecode for supported Paper servers.

## Changes

- Recognize only demonstrably equivalent Adventure name/lore component trees, including the same ordered lore lines. Colors, decorations, click/hover events, insertion text, translatable components and meaningful styled wrappers are **not** ignored.
- Require identical, non-null registered Slimefun item IDs and matching functional ItemStack metadata before treating old and current presentation as equivalent. Material, PDC, model, owner and other item identity fields remain protected. Vanilla and unidentified items do not enter this compatibility fallback.
- Compare the actual live storage template rather than a stale memoized ItemMeta snapshot when handling matching input. Preserve original transport behavior and the physical output buffer.
- On a safe, empty-buffer storage tick, reserialize only the protected private display template to its canonical equivalent. The repair does **not** rewrite `stored_amount`, `void_excess`, or player inventories, and it preserves the private display marker byte actually present when the repair starts. A legacy GUI redraw may independently regenerate this display-only marker during normal world loading.
- Verify template writes and attempt identity-safe rollback on failure; refuse further transfer if the protected slot cannot be reconciled. Never replace another owner's or another Slimefun item's template, fabricate a refund, or reset a stored amount.

## Verification and limitations

The underlying storage fix passed exact-head builds on Paper 1.21.11 and 26.3, the four-version candidate-core validation matrix, the full regression suite and migration/transport safeguards. After merging, the exact `master` commit was validated again with native Paper 1.21.11/Java 21 and Paper 26.3/Java 25.

Disposable native tests seeded a real storage unit with the published IE2 2.0.17 plugin. They verified the historical wrapped item and its 731-unit ledger, registered ID, lore, Void Excess setting, and physical output after an actual registered Forge craft, SIGKILL of the disposable JVM, and restart. Both the first repair and post-restart re-repair retained the pre-tick display marker byte. The release build is independently gated on exact-source CI, Java 21 packaging and the versioned JAR artifact.

These tests are not proof of every historical world configuration, arbitrary crash instruction, every custom addon combination, or Folia cross-region behavior. Recipes, rates, capacities, item/research IDs and existing data formats are not intentionally changed. No Bedrock or Geyser logic is introduced.

## Installation

Stop the server; back up the world, Slimefun block storage and InfinityExpansion2 data/configuration. Replace the previous InfinityExpansion2 JAR with `SF_InfinityExpansion2.0.18.jar` only—do not leave two addon versions in the plugins directory—and restart normally, not with `/reload`. Preserve existing data. To roll back, restore a matching pre-upgrade data backup alongside the older addon JAR. Nothing is automatically deployed to a live server.
