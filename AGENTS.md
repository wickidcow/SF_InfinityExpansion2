# InfinityExpansion2 maintenance contract

Target Minecraft 1.21.11 and newer, prioritizing Paper/Purpur and retaining appropriate Leaf/Folia validation. Saved items, storage contents and machine state can be older than the runtime floor. Preserve IDs, research, recipes, quantities, rates, persistent keys/types, stored inventories, ownership, transport order and existing migration policy.

Do not mechanically replace BlockStorage or remove a historical reader to eliminate warnings. Keep migrations opt-in and retain fresh fingerprint/confirmation/provider guards. Missing addons, unreadable records and failed metadata copies must not become permission to erase data or pretend conversion succeeded. The existing explicit legacy-to-IE2 mapping is distinct from reconstructing all player items from current templates. Do not enable or broaden it incidentally.

Build with the checked-in Gradle wrapper and an exact Slimefun API published locally. The core used for candidate tests must be recorded. Keep the MockBukkit Paper test API separate from the production compile matrix; test-only dependencies must not enter the plugin JAR. Current canonical output is `build/libs/SF_InfinityExpansion2.0.18.jar`; synchronize version and CI names only during a coordinated, validated version bump.

Run the full build and all six existing migration/Doctor/mob-simulation/transport source checks. Keep English-facing diagnostics and docs. Preserve concurrent branch changes, use coherent regression-tested batches, and report actual compiler/runtime evidence separately from lexical source matches. A compile is not a live world upgrade or cross-fork rollback certificate. Audit branches are eligible for autonomous completion under the repository owner's standing authorization. Do not require repeated owner approval to merge a verified audit/fix PR or publish a distinct follow-up release. To merge, first review the full diff and resolve review threads, conflicts, and concurrency; verify all required CI, the full Gradle build, the six migration/Doctor/mob-simulation/transport source checks, and focused regression tests. For changes to item presentation, storage, cargo, persistence, migration, or conservation, require exact-head native Paper validation, historical saved-data and restart evidence, and no unresolved loss, duplication, or compatibility blocker. A passing compile or lexical check alone is insufficient. Merge through the normal protected pull-request path only when all applicable checks and repository policies are satisfied; never bypass protections, merge a draft or failing PR, or overwrite another agent's changes.

After a successful merge and fresh verification on the exact default-branch commit, autonomous version bumps and publication of a **new, distinct** release are permitted if the required post-merge CI, runtime/compatibility evidence, packaging and artifact checks pass. Publish only from a pinned default-branch commit, never directly from an unmerged audit branch. Keep previously published tags and assets immutable. If any required check or release evidence is missing or failing, leave the PR or release unpublished and document the blocker; owner approval is not a substitute for required safety gates.
